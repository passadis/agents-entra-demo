Where identity is enforced

The framework runs the agent's model/tool loop. Each protected tool independently acquires and verifies a resource token for the configured regional Entra agent identity. The model cannot choose a different identity or grant itself permissions. The host managed identity authenticates model access and blueprint federation; it is a separate principal.

Audit trail

Operator requests, tool calls, policy refusals, approvals, and orders share a run ID. Entra sign-in logs are a separate tenant record.

Operating the agentic demo

01 / TWO WORKING AGENTS

Run each depot

  1. Select Piraeus, then Replenish the depot.
  2. Watch inventory and supplier tool results. The agent should choose the available offer meeting the delivery deadline and create a €420 order for 100 seals.
  3. Select Newark and repeat. Its separate identity should create a €380 order for its own depot.
  4. Expand verified identity evidence and compare each principal with the registry.

Incoming orders count toward inventory. Repeating replenishment may correctly produce no new order. To demonstrate another purchase, explicitly request a quantity, such as “Order 20 additional safety seals for my depot, delivery within 12 hours.”

02 / HUMAN OVERSIGHT

Approve and resume

Run Urgent engine sensor with either agent. Review the exact supplier, quantity, regional scope, and server-calculated total. Approve as the configured sponsor, or reject. The saved framework session resumes with your decision.

Approval does not override missing roles, regional scope, suspension, review expiry, or the €5,000 ceiling. Controls are checked again before the order is recorded.

03 / ENFORCED BOUNDARIES

Explore refusals

Spending boundary exceeds the ceiling. Cross-region request targets the other depot. The tools enforce both boundaries even if the model attempts the action.

Untrusted supplier note places an adversarial instruction in a synthetic supplier result. The agent should reject it. There is no bank export tool or external transfer capability. A model refusal is different from a server-enforced tool denial; inspect the evidence.

For a free-text procurement task, select Allow this request to create one fictional order within policy. Otherwise the server permits research only. Scenario cards include their own task authority.

04 / LIFECYCLE & EVIDENCE

Pause, inspect, restore

Pause the class or suspend an agent, then submit a request. Expire a review to demonstrate lifecycle policy. Restore active status and renew reviews afterward.

Use the previous-run selector for pending approvals. Export the audit trail for correlated evidence. Controls change application policy; they do not disable Entra directory objects.

Real model calls and framework execution use synthetic business records. Runs have tool, time, and iteration limits. Conversation checkpoints persist server-side; raw tokens are never shown.
